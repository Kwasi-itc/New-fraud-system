## New supporting objects (proposed, not present in source)

| Object | Key/columns and invariant | Owner / gate |
|---|---|---|
| data_model_physical_objects | PK tenant/table, unique physical_name, published_version, write_state, desired_operation | Model; POC-04 and exact imported-ID profile |
| data_model_schema_operations | operation UUID PK, tenant/table, request_hash, expected/target version, desired shape, state/error/timestamps | Model; P-01 idempotent recovery |
| id_membership_roles | tenant/user/role composite PK, FK tenant/user membership; validated role domain | Identity; roles/version updates in same transaction |
| owner_exact_key_buckets | owner-specific table; tenant/domain/digest key and stable locking row | Owning service; restricted allocation and forced-collision proof |
| owner_exact_keys | key UUID, tenant/domain/digest, full canonical bytes; tenant/key unique for references | Owning service; only allocator writes; no hash-only identity |
| owner_operation_guards | narrow typed scope/key, stable reservation; bounded lifetime policy decided explicitly | Owner; row lock serializes missing-resource operations |
| owner_jobs | immutable job ID/kind/queue/payload version, state/availability, attempt/token/lease, limits/error/timestamps | Owner; P-03 and Q-01 lifecycle |
| owner_active_jobs | exact dedupe scope -> active job reference | Owner; transactional reservation/release and active-state parity |
| owner_schedules/occurrences | schedule state plus unique schedule/scheduled_instant occurrence | Owner; restart/misfire/RunOnStart policy and transactional watermark |

`owner_` is a specification placeholder, not a shared unrestricted runtime table. Instantiate only mechanisms that the owner actually uses; avoid redundant job tables for services without that work. DDL registry/operation lifecycle is model-owned. Dynamic tenant tables are mapped separately by `(tenant_id, table_id)` to `td_<physicalUUID>`; all original base and model fields remain represented. Generated conditional unique columns and hidden exact-key references require per-table manifest entries and enforced write contracts, not blanket automatic application.
