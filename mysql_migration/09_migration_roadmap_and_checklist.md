# Dependency-aware roadmap

No migration implementation is authorized by this audit. Every M task is **NOT_STARTED**. A task may move to IN_PROGRESS, BLOCKED, NEEDS_REVIEW or COMPLETED only with dated evidence and an owner. Documentation tasks are separate from runtime readiness. Tasks below encompass every PG family; detailed occurrence lists in 11 are the implementation checklist within each task.

M-11 can proceed alongside M-06–M-09 after foundations. Cross-owner contract specifications must be agreed before implementing their callers; integration completion waits for both sides. These coordination dependencies do not require moving live services one at a time. Keep production PostgreSQL until all shared-schema consumers are ready for coordinated cutover.

## Gate checklist

- [x] Source evidence, historical-plan distinction and documentation-only boundary recorded.
- [x] Every PG family maps to compatibility treatment and future task.
- [ ] Runtime catalog, data volumes and measurable goals approved (M-01).
- [ ] Naming/type/uniqueness, recoverable DDL and queue feasibility proven (M-02–M-06).
- [ ] All service/identity/investigation invariants verified (M-07–M-11).
- [ ] Deployment/tooling, transfer and restore rehearsed (M-12–M-13).
- [ ] Correctness/performance gate passes (M-14).
- [ ] Cutover authorization, execution and stabilization complete (M-15–M-16).

Record future results with source hash, engine versions, exact commands, environment identity, passed/failed/skipped counts, plan/workload artifacts and unresolved risks. Do not mark a task complete based only on compiling SQL or changing a URL.
