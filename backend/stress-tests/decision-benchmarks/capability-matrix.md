# Capability matrix

This is a production-path inventory, not a promise that every catalog entry works in every deployment. **Implemented** means code paths exist, not that this audit executed them. **Conditional** adds a configuration/dependency requirement. **Partial/disabled** is excluded from successful-performance cohorts and included in rejection tests.

Primary references: [AST model](../../decision-engine-service/internal/domain/ast/model.go), [catalog](../../decision-engine-service/internal/runtime/ast_eval/catalog.go), [ValidateNode](../../decision-engine-service/internal/runtime/ast_eval/validation.go), [evaluateNodeUncached and helpers](../../decision-engine-service/internal/runtime/ast_eval/evaluator.go), [evidence evaluation](../../decision-engine-service/internal/runtime/ast_eval/evidence.go), [aggregate compiler](../../decision-engine-service/internal/runtime/ast_eval/aggregate_compiler.go). These files jointly define support; the catalog alone is insufficient.

## Input contract and notation

Examples use `F("amount")` as documentation shorthand for `{"function":"field_ref","named_children":{"field":{"constant":"amount"}}}` and `C(x)` for `{"constant":x}`. `op(a,b)` means `{"function":"op","children":[a,b]}`. Shorthand is not accepted API syntax. `Payload` uses a positional field-name constant; `field_ref` uses a named field. Field names refer to the flat `fields` map, not a `transaction.` path prefix. Field-to-field comparison uses two accessor nodes.

Rules and triggers must return boolean. Numeric, timestamp, list and object helpers require a boolean wrapper where appropriate. Full payload validation happens before AST evaluation: required omission/null is rejected; nullable omission normalizes to null; unknown fields are rejected. The scalar model supports bool, int, float, timestamp, ip_address and string; arbitrary arrays/objects in transaction fields are not a supported model type. AST list/object constants and computed lists are a different capability.

## Scalar and structural capabilities

| Family / status | Operators and input requirements | Validation and evaluation behavior / benchmark implications |
|---|---|---|
| Literals/accessors — implemented | `constant`, empty-function constant; `field_ref(field)`; `Payload` with one string child | Model validation requires known fields. Runtime map lookup returns null for absent fields. No distinct missing-key predicate. JSON alias `name` is supported; canonical names preferred for generated fixtures |
| Numeric — implemented | `eq`, `neq`, `gt`, `gte`, `lt`, `lte`; symbolic aliases in canonicalizer | Two compatible operands. Range = `and(gte(...),lt(...))`, not a dedicated BETWEEN. Exact numeric operands use rational comparison to preserve int64 identity; arithmetic still uses float64. Test above 2^53 and int64 bounds separately from decimal arithmetic |
| Arithmetic — implemented | `add`, `subtract`, `multiply`, `divide` (two numeric children); `IsMultipleOf` named `value`, `divider` | Numeric helper result must be compared to produce boolean; divide by zero fails. Divisibility has integer restrictions in evaluator; include zero/nonintegral divider negative tests |
| String equality/order — implemented | `eq`, `neq`, `gt`, `gte`, `lt`, `lte`; `lower`, `upper` take one string | Ordinary comparisons are case-sensitive. RFC3339-looking strings are parsed as timestamps before ordinary string comparison; mixed parseable/nonparseable operands can error. Do not assume every string comparison is lexical |
| String patterns — implemented | `contains`, `StringNotContain`, `starts_with`, `ends_with`: two strings; `ContainsAnyOf`, `ContainsNoneOf`: string + list of strings | Literal substring/prefix/suffix operations. No general regex-match or SQL-LIKE rule operator found; regexp package usage elsewhere does not establish one. Explicit lower/upper normalization for case-insensitive rules |
| Membership — implemented | `in(value,list)`, `contains(list,value)`, `IsInList`, `IsNotInList`, `List` children | Validator checks list shape; element comparisons use evaluator semantics and can fail on incompatible elements. Empty list and mixed element types are required cases. Core `in` and compatibility `IsInList` are separate branches; test aliases independently |
| Boolean logic — implemented | `and`, `or`: one or more boolean children; `not`: one boolean; boolean `eq`/`neq` | Nested trees supported. AND/OR short-circuit left to right, skipped evidence retained. Validator rejects empty AND/OR even though direct runtime loops have identities. Boolean ordering rejected; compatibility symbolic aliases need their own validation parity tests |
| Null/empty — implemented | `is_null(x)`, `IsEmpty(x)`, `IsNotEmpty(x)`, `coalesce(children)` | Empty tests cover null/empty string, not arbitrary collection emptiness. `not(is_null(F))` tests non-null, not key existence. `eq(null,null)` true; `neq(null,value)` true for non-null value; ordered comparisons with null false. Coalesce returns first non-null child |
| Field-to-field — implemented | e.g. `gt(F("amount"),F("limit_amount"))` | Both fields must be declared and compatible. No special cross-field DSL required |
| Dates/time — implemented | Timestamp comparisons; `ParseTime` one child; `TimeNow`; `TimeAdd` named `timestampField`, `duration`, `sign`; `TimestampExtract` named `timestamp`, `part` | RFC3339/RFC3339Nano parsed to UTC. Extract supports year, month, day_of_month, day_of_week, hour. TimeAdd accepts Go durations and a limited P/DT/H/M/S parser, not arbitrary calendar arithmetic. Pin supported strings such as `PT5M`; malformed duration acceptance deserves negative tests. Use explicit inclusive/exclusive bounds |
| String construction — implemented | `StringConcat` children plus optional `with_separator`, `separator`; `StringTemplate` template child plus named variables | Runtime validates supported rendering types; no implicit general-purpose scripting. Wrap string result in comparison |
| Fuzzy similarity — implemented | `FuzzyMatch` two strings; `FuzzyMatchAnyOf` string/list; named `algorithm` | Local score 0..100 via ratio/direct_string_similarity_db or token_set_ratio/bag_of_words_similarity/bag_of_words_similarity_db. Null input returns null. AnyOf can stop on score 100; varies with text/list size. Algorithm names containing `_db` do not imply a network/database call here |
| Fuzzy options — partial as database filter feature | `FuzzyMatchOptions(algorithm,threshold,value)` returns an options object; threshold 0..100 | Object construction exists, but this does not establish fuzzy aggregate SQL support. Aggregate filter compiler supports only the operators listed below |
| Conditional score objects — implemented helper, not scenario scoring replacement | `ScoreComputation`: boolean child, numeric modifier, optional floor; `Switch`: field guard, score-result branches, optional fallback; `object_get` | Results are objects and cannot stand alone as boolean rule formulas. Scenario score still adds the rule's stored modifier. Switch computes branches before choosing first triggered result; do not assume AND-like short circuit. Evidence traverses children too. Benchmark only boolean extraction/wrapping that passes validation; include fallback-error behavior as a reliability case |
| In-memory collection helpers — implemented | `filter_eq(items,field,value)`, `map_field(items,field)`, `list_count`, `sum`, `avg`, `min`, `max`, `group_count(items,field)`, `group_sum(items,group_field,value_field)`, `object_get(object,key)` | Lists from constants/computed helpers; runtime verifies items and numeric contents. Empty numeric-list results follow `aggregateNumericList`, not necessarily SQL aggregates. No enabled broad-history source is implied; model payload arrays remain unsupported |

## Data-dependent capabilities

| Family / status | Arguments and validation | Production path / limitations |
|---|---|---|
| Historical aggregate — conditional | `Aggregator` named `tableName`, `fieldName`, `aggregator`, optional `filters`, label; model table/field and aggregator type checks | Compiler supports COUNT, COUNT_DISTINCT, SUM, AVG, MIN, MAX only. Requires enabled pushdown and aggregate allow-list. Calls `TenantDataReader.AggregateRecords`; never falls back to listing all history |
| Aggregate filters — conditional | `Filter` named `fieldName`, `operator`, optional `value` (tableName is accepted by authoring forms); `List` means conjunction; nested AND/OR/NOT | Compiler supports `= / eq`, `!= / neq`, `> / gt`, `>= / gte`, `< / lt`, `<= / lte`, `IsInList` with resolved list, `StringStartsWith` with resolved string. Null eq/neq become IS NULL/IS NOT NULL. Same-field OR equalities can collapse to IN. Values can resolve from payload or TimeAdd/TimeNow |
| Other aggregate filters — partial/unsupported | Validator understands additional compatibility filters including `IsNotInList`, empty checks and `StringEndsWith` | They are not all accepted by `normalizeAggregateFilterOperator`. Suffix explicitly rejected. Do not infer scalar/filter equivalence. SQL NOT and NULL use SQL three-valued semantics; test against an independent SQL-aware oracle |
| Statistical aggregates — partial/unreachable on production Aggregator path | Validation/helpers recognize STDDEV, PCTILE, MEDIAN (PCTILE includes percentile argument) | Compiler rejects these; older local helper implementations do not make them working live rules. Historical average comparisons work via AVG; deviation/percentile baselines do not currently qualify |
| Velocity/repetition — conditional composition | COUNT/SUM plus customer/merchant/destination equality and explicit timestamp filters | No independent velocity-counter service/operator in this path. Current payload is included only if independently ingested and selected. Frequency can be derived from count and arithmetic; guard zero denominators |
| Related single record — conditional | `related_field(path,field)` or `DatabaseAccess(tableName,fieldName,path)`; declared model links | `TraverseRelatedPath` issues bounded parent-key queries per hop; no missing relationship => null. Requires model and reader, and correct parent uniqueness/indexes. Does not scan arbitrary history subsets |
| Broad related history — disabled | `related_count`, `related_records` still appear in catalog/validation | Runtime always rejects with broad-read-disabled error. Existing benchmark variants using them require replacement with supported Aggregator or explicit rejection cohorts |
| Decision history — implemented with scaling risk | `past_decision_count`, optional named outcome | Loads all decisions for tenant/object/type, then filters/counts in Go; no time-window argument. Concurrent evaluation writes change the counted state |
| Platform membership — conditional | `in_custom_list(list,value)`; `CustomListAccess` named customListId | Repository lookup/list retrieval. Identity/name forms differ; provision via platform API and validate tenant ownership. List-returning form can increase memory and fuzzy cost with list size |
| Tags/risk/flags — conditional | `record_has_tag(tag)`, `record_risk_level`, `has_ip_flag(ip,flag)` | Decision-owned platform repositories scoped to tenant and record/IP; risk is latest-snapshot lookup and must be compared. Fixtures must provision values, absence and cross-tenant lookalikes |
| GeoIP — conditional | `IPCountry`, `IPCountryCode`, `IPRegion`, `IPRegionCode`, `IPContinentCode`, `IPGeoFound` (canonical snake names also supported), exactly one positional IP child | Validation requires ip_address data-model field. Configured local MMDB provider plus per-evaluation cache; missing database/provider differs from absent IP location. Record database version/build, IPv4/IPv6 and lookup miss cases |

## Composition and configuration restrictions

- Rules in a scenario combine by score addition. `rule_group` and `display_order` do not implement AND/OR grouping or first-hit rule execution. Logical combination belongs inside formulas.
- Scenarios return separate results. Scenario priority or a global winner is not represented by `scenario.Scenario`; workflow rule priority is a different downstream feature.
- Full setup sequence: create model/fields and links; create scenario; create draft iteration; set trigger/thresholds; create rules; validate; commit; prepare required indexes; publish; verify live state. Repeat smoke evaluation with exact intended configuration before measuring.
- Exact comparison of prepared integers does not establish exact parsing of large numeric AST literals: `Node.UnmarshalJSON` decodes `Constant any` with ordinary `json.Unmarshal`, which produces float64 numbers. Include large field-to-field comparisons and large JSON-literal comparisons as distinct fidelity cases; do not derive the oracle from rounded AST values.
- Supported aggregate SQL does not imply it is enabled: Go defaults count; current root Compose count,sum,avg,count_distinct; isolated service pilot all six. Record effective API **and worker** settings.
- Unsupported rule types remain useful correctness tests, never successful fraud-evaluation throughput samples. Unexpected acceptance/rejection is an anomaly to investigate, not something the harness should silently repair.
